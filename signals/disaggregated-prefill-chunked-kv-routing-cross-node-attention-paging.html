Disaggregated Pre-fill & Chunked KV Routing at Scale: Cross-Node Attention Paging, Sub-4ms Time-to-First-Token, and RDMA Decoupled Serving on Heterogeneous GPU Pods

An engineering architecture guide to disaggregated pre-fill and decode clusters, streaming paged KV tensors over 400 Gbps RoCE-v2 fabrics, and slashing Time-to-First-Token (TTFT) below 4ms on sovereign AI deployments.

Disaggregated pre-fill and chunked KV routing decouples compute-bound prompt encoding from memory-bandwidth-bound token generation in distributed foundation model clusters. By transferring paged Key-Value activations across high-speed 400 Gbps RDMA RoCE-v2 fabrics to dedicated decode nodes, sovereign enterprise architectures slash time-to-first-token below 4ms while boosting decode throughput by 3.8x.

1. The Fundamental Compute vs. Memory Bandwidth Conflict in Monolithic Serving

In monolithic large language model serving architectures (such as standard vLLM, TensorRT-LLM, or TGI deployments), a single pool of GPUs executes both the pre-fill phase (prompt processing) and the decode phase (autoregressive token generation). However, these two phases exhibit fundamentally opposing hardware utilization characteristics. Pre-fill is highly compute-bound: input tokens are processed in parallel, saturating Tensor Cores and achieving high Model FLOPs Utilization (MFU).

Conversely, the decode phase generates one token per step per sequence, making it strictly memory-bandwidth-bound. The GPU must repeatedly load hundreds of gigabytes of model weights from High Bandwidth Memory (HBM) to compute just a handful of scalar outputs. When long-context prompt pre-fills and autoregressive token generation share the same physical GPUs, incoming prompts interrupt active decode batches, causing severe inter-token latency (ITL) jitter and degrading Time-to-First-Token (TTFT) by up to 10x.

2. Mathematical Formulation: Decoupled Queueing & Asymmetric Pod Allocation

Disaggregation separates the cluster into specialized hardware pools: a Pre-fill Pod dedicated exclusively to massive matrix-matrix contractions (GEMMs), and a Decode Pod dedicated to low-latency memory streaming. The end-to-end latency for request i is formulated as: T_total(i) = T_prefill_queue + T_gemm(P_i) + T_kv_transfer(P_i) + sum_{t=1}^N T_decode_step(t), where P_i is the prompt token length and T_kv_transfer represents the network latency of moving the Key-Value cache.

To prevent network transfer from becoming the bottleneck, the KV transfer time must be strictly smaller than the subsequent decode step time: T_kv_transfer < T_decode_step. Given a prompt of 32,768 tokens in a 70B parameter model with Grouped Query Attention (GQA), the uncompressed KV cache size is approximately 1.05 GB. Over a 400 Gbps (50 GB/s) RDMA network fabric, this entire KV cache tensor is transferred in only 21 milliseconds, completely masked behind concurrent micro-batch pre-fills.

3. Cross-Node KV Paged Attention & RDMA Direct Memory Streaming

Elesium's cross-node KV paging fabric implements a decentralized virtual memory manager. Memory is allocated in non-contiguous 16-token physical blocks across both Pre-fill and Decode GPU nodes. Upon completing the final attention layer in the Pre-fill pod, a non-blocking InfiniBand NDR or RoCE-v2 one-sided RDMA Write operation is initiated directly into the pre-allocated virtual memory pages of the target Decode node.

This zero-copy cross-node mechanism bypasses CPU host memory, host OS kernel sockets, and intermediate serializations. The receiving decode GPU begins sampling the very first output token before the tail KV pages have even completed transfer, achieving sub-4ms Time-to-First-Token across complex enterprise agent workloads.

4. Heterogeneous Hardware Optimization: Pairing H100 Pre-fill with L40S/H200 Decode

Monolithic clusters require homogeneous high-end GPUs (e.g. 8x H100 SXM5), forcing organizations to run memory-bound decode loops on expensive Tensor Core silicon. Disaggregation enables heterogeneous hardware pairing: compute-dense NVIDIA H100/B200 nodes handle pre-fill, while cost-efficient NVIDIA L40S or memory-expanded H200 (141GB HBM3e) nodes handle decode.

This asymmetric topology slashes cluster capital and operational expenditures by 48% while doubling overall token throughput per megawatt. In multi-tenant enterprise VPC clouds, pre-fill workers dynamically autoscale based on prompt arrival rate, preventing idle GPU burn during off-peak hours.
