Pydantic Schemas for Structured Output --- class GuardrailValidation(BaseModel): is_safe: bool = Field( description="True if clinical output adheres to ICMR guidelines and lacks hallucinations." ) flagged_reason: str = Field( description="Reason for rejection if unsafe, else None." ) # --- 3. Node Implementations --- def pii_redaction_node(state: ClinicalState) -> ClinicalState: """Simulates localized PII scrubbing compliant with DPDP Act 2023.""" text = state["raw_input"] # Mock redaction logic for Indian identifiers (Aadhaar, ABHA, Phone) redacted = ( text.replace("Aadhaar:", "[REDACTED-ID]") .replace("Phone:", "[REDACTED-PHONE]") .replace("ABHA:", "[REDACTED-ABHA]") ) log = "PII Redaction Node executed successfully under DPDP compliance." return { "anonymized_text": redacted, "audit_logs": [log], } def fine_tuned_inference_node(state: ClinicalState) -> ClinicalState: """Invokes the private fine-tuned healthcare LLM inside a private VPC.""" prompt = state["anonymized_text"] # Simulated model generation utilizing fine-tuned medical weights simulated_output = ( f"Clinical Diagnosis Summary for input: {prompt}. " "Recommended Action: Correlate with CBC and ESR panels." ) log = "Fine-tuned model inference executed on isolated V100/A100 GPU cluster." return { "model_output": simulated_output, "audit_logs": [log], } def deterministic_guardrail_node(state: ClinicalState) -> ClinicalState: """Validates output against clinical safety boundaries.""" output = state["model_output"] # Enforce reliable validation check if "CBC" in output: validation = GuardrailValidation( is_safe=True, flagged_reason="Passed validation." ) else: validation = GuardrailValidation( is_safe=False, flagged_reason="Missing mandatory lab correlation." ) status = "APPROVED" if validation.is_safe else "REJECTED" log = f"reliable Guardrail validation status: {status} ({validation.flagged_reason})" return { "validation_status": status, "audit_logs": [log], } # --- 4. Adapting foundation models (such as Llama-3-70B, Mistral-8x22B, or Indic-specific LLMs like Sarvam-1) to Indian healthcare requires balancing computational efficiency against domain-specific precision.

### 4.1 Parameter-Efficient Fine-Tuning (PEFT) Strategies * **LoRA (Low-Rank Adaptation):** Injects trainable rank decomposition matrices into attention layers ($W_q, W_v$). This reduces trainable parameters by up to 99%, making on-premise fine-tuning feasible on local GPU clusters (e.g., NVIDIA DGX or local enterprise servers). * **QLoRA (Quantized Low-Rank Adaptation):** Combines 4-bit NormalFloat (NF4) quantization with double quantization and paged optimizers. QLoRA enables fine-tuning of 70B parameter models on a single 80GB A100 GPU without degradation in clinical perplexity scores. * **Full-Parameter Fine-Tuning:** Reserved for foundational base model adaptation where custom vocabulary tokens (such as regional medical abbreviations) must be embedded directly into the embedding matrix.

### 4.2 Hyperparameter Tuning for Clinical Corpora To prevent major forgetting of general reasoning capabilities while instilling domain expertise, we utilize the following hyperparameter profile: * **Learning Rate:** $1.5 \times 10^{-5}$ with cosine schedule and 3% warm-up steps. * **Batch Size:** Gradient accumulation steps set to 16 to achieve an effective batch size of 128. * **Context Window:** 8,192 tokens to accommodate multi-page patient discharge summaries and clinical history.
